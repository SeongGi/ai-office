# 02 설계: 데스크톱 앱 설치형 만들기

이 문서는 `01-요구사항.md`을 전제로 한다. 설계 검토 결과는 맨 아래 절에 반영 이력으로 남긴다.

## 전체 그림

설치 명령은 npm의 `electron` optionalDependency가 이미 받아 둔 `node_modules/electron/dist/Electron.app`을 복사해, 이름과 아이콘만 "AI Office"로 바꾸고 다시 서명한 뒤 `~/Applications`에 둔다. 앱 코드는 복사하지 않는다. 번들 안의 `Contents/Resources/app/index.js`가 저장소 경로의 `desktop/main.cjs`를 그대로 `require`하므로, 지금 Electron으로 띄우는 것과 실행되는 코드가 똑같다. 달라지는 것은 겉모습(이름, 아이콘, Dock·메뉴 표시)뿐이다.

## 새 모듈: `desktop/installer.cjs`

기존 `desktop/*.cjs` 파일들과 같은 방식(CJS, `bin/ai-office.mjs`에서 `createRequire`로 불러씀)으로 만든다.

```
exports.installApp = function installApp() { ... }   // { ok, error? , path? }
exports.uninstallApp = function uninstallApp() { ... } // { ok, error?, removed }
```

### 상수

- `APP_NAME = 'AI Office'`
- `BUNDLE_ID = 'com.ai-office.desktop'` (특정 개인·조직에 매이지 않는 값. 이 저장소를 포크해 쓰는 사람도 그대로 쓸 수 있다.)
- `destDir() = path.join(os.homedir(), 'Applications')`
- `destApp() = path.join(destDir(), `${APP_NAME}.app`)`

### 순수 함수로 뺄 부분(Electron·macOS 도구 없이 테스트한다)

요구사항의 성공 기준 9번(Electron 없이도 테스트할 수 있는 부분에는 테스트가 있어야 한다)을 지키려고, 실제로 파일을 건드리거나 외부 명령을 부르는 코드와, 계산만 하는 코드를 나눈다.

- `resolveTemplateApp(electronBinPath)` 템플릿 Electron.app 경로를 계산하고 검증한다. `electronBinPath`는 `.../Electron.app/Contents/MacOS/Electron` 형태여야 하고, 세 단계 위(`dirname` 세 번)로 올라간 경로의 마지막 구성 요소가 `Electron.app`이 아니면 `{ ok: false, error: 'electron 패키지 구조가 예상과 달라요(...). electron 버전을 확인해 주세요.' }`을 돌려준다. 성공하면 `{ ok: true, path }`.
- `iconsetFiles()` macOS `.iconset` 규칙에 맞는 `{ name, size, template }` 목록을 돌려준다(`icon_16x16.png`(16px), `icon_16x16@2x.png`(32px), `icon_32x32.png`(32px), `icon_32x32@2x.png`(64px), `icon_128x128.png`(128px), `icon_128x128@2x.png`(256px), `icon_256x256.png`(256px), `icon_256x256@2x.png`(512px), `icon_512x512.png`(512px), `icon_512x512@2x.png`(1024px)).
- `buildAppStubSource(repoRootPath)` `Contents/Resources/app/index.js`에 쓸 소스 코드 문자열을 돌려준다. `JSON.stringify(repoRootPath)`로 경로를 문자열 리터럴로 안전하게 넣는다(경로에 공백이나 따옴표가 있어도 깨지지 않아야 한다. 다른 사용자의 저장소 경로는 우리가 고를 수 없다).
- `isOurApp(identifier)` 기존 `destApp()`의 `CFBundleIdentifier`가 `BUNDLE_ID`와 같은지만 비교하는 함수(외부 명령 호출 없이).
- `plistEdits(values)` Info.plist에 적용할 `{ key, type, value }` 목록을 돌려준다(`CFBundleName`/`CFBundleDisplayName`/`string`/`AI Office`, `CFBundleIdentifier`/`string`/`BUNDLE_ID`, `CFBundleExecutable`/`string`/`AI Office`, `CFBundleIconFile`/`string`/`icon`, `CFBundleShortVersionString`·`CFBundleVersion`/`string`/저장소 `package.json`의 `version`). 실제 `PlistBuddy` 호출은 별도 함수가 이 목록을 순서대로 실행한다.

### 실제로 파일·외부 명령을 다루는 부분

1. `process.platform !== 'darwin'` → `{ ok: false, error: '이 설치는 macOS에서만 됩니다. 다른 OS에서는 `ai-office`로 브라우저 창을 쓰세요.' }`.
2. `electron` 바이너리 경로 얻기: `let electronBin; try { electronBin = require('electron'); } catch { return { ok: false, error: 'electron이 설치되어 있지 않습니다. `npm ci` 이후 다시 시도하세요.' }; }` 문자열이 아니거나 `fs.existsSync`가 거짓이면 같은 식으로 에러.
3. `resolveTemplateApp(electronBin)` 호출 → 실패하면 그대로 반환.
4. 기존 설치 확인: `destApp()`이 있으면 `/usr/libexec/PlistBuddy -c "Print :CFBundleIdentifier" <destApp>/Contents/Info.plist`를 읽어(`spawnSync`) `isOurApp(값)`이 거짓이면 `{ ok: false, error: '~/Applications/AI Office.app 자리에 이미 다른 앱이 있어서 설치를 멈췄습니다. 그 앱을 다른 이름으로 옮긴 뒤 다시 실행해 주세요.' }`. `PlistBuddy` 호출 자체가 실패해도(= Info.plist를 읽을 수 없음) 같은 식으로 안전하게 멈춘다.
5. 임시 작업 폴더 만들기: `fs.mkdtempSync(path.join(os.tmpdir(), 'ai-office-install-'))`. 실패·중단 시 기존 앱은 전혀 건드리지 않은 상태로 남는다(마지막 한 걸음에서만 `destApp()`을 옮긴다).
6. `spawnSync('ditto', [templateApp, tmpApp])`로 템플릿을 복사한다. 결과가 0이 아니면 에러로 멈추고 `tmpApp`은 지운다.
7. `fs.renameSync(tmpApp/Contents/MacOS/Electron, tmpApp/Contents/MacOS/AI Office)`.
8. `plistEdits(...)`의 각 항목마다 `/usr/libexec/PlistBuddy -c 'Delete :<key>' <plist>`(실패 무시, 키가 원래 없을 수 있다) 다음 `/usr/libexec/PlistBuddy -c 'Add :<key> <type> "<value>"' <plist>`(실패하면 에러로 멈춘다). 값은 큰따옴표로 감싸 PlistBuddy가 공백을 하나의 토큰으로 읽게 한다. `AI Office`처럼 공백이 든 값을 위해 필요한 처리이고, PlistBuddy 매뉴얼의 `-c` 설명에 적힌 인용 규칙을 따른 것이다.
9. 기존 `Contents/Resources/electron.icns`를 지운다(이름을 "icon.icns"로 새로 두므로 혼동을 피한다).
10. `iconsetFiles()`의 각 항목을 `desktop/icon.cjs`의 `markPng(size, { background: true })`로 그려 임시 `.iconset` 폴더에 PNG로 쓰고, `spawnSync('iconutil', ['-c', 'icns', iconsetDir, '-o', path.join(tmpApp,'Contents/Resources/icon.icns')])`. 실패하면 에러.
11. `Contents/Resources/app/` 폴더를 만들고 `package.json`(`{"name":"ai-office-desktop-app","version":<repo version>,"main":"index.js"}`)과 `index.js`(`buildAppStubSource(repoRoot())`의 결과)를 쓴다.
12. `spawnSync('codesign', ['--force', '--deep', '--sign', '-', tmpApp])`. 실패하면 에러로 멈춘다(요구사항의 가장 큰 운영 위험이라 여기서 멈추면 반드시 알아챈다).
13. `spawnSync('xattr', ['-cr', tmpApp])`(격리 속성 제거, 실패해도 무시해도 되는 보조 단계).
14. `fs.mkdirSync(destDir(), { recursive: true })`; 4번에서 기존 앱이 우리 것으로 확인됐다면 `fs.rmSync(destApp(), { recursive: true, force: true })`; `fs.renameSync(tmpApp, destApp())`. `rename`이 `EXDEV`(다른 볼륨)로 실패하면 `ditto`로 옮기고 `tmpApp`을 지우는 것으로 바꾼다.
15. `{ ok: true, path: destApp() }`를 돌려준다.

각 단계에서 에러가 나면 그 시점까지 만든 임시 폴더를 지우고 멈춘다(`finally`에서 `tmpApp` 정리). `destApp()`은 14번 전까지 전혀 건드리지 않으므로, 설치 중 어디서 실패해도 기존 상태가 유지된다.

### 삭제 (`uninstallApp`)

1. `destApp()`이 없으면 `{ ok: true, removed: false }`(지울 게 없으니 성공으로 본다).
2. 있으면 `isOurApp(...)` 확인(설치와 같은 방식). 다르면 `{ ok: false, error: '...우리가 만든 앱이 아니라서 지우지 않았습니다.' }`.
3. 같으면 `fs.rmSync(destApp(), { recursive: true, force: true })` 후 `{ ok: true, removed: true }`.

## `bin/ai-office.mjs` 변경

- `commands` 객체에 `'install-app': installAppCmd` 추가.
- `installAppCmd(args)`: `flags(args)`로 `--uninstall` 읽기 → `require('../desktop/installer.cjs')`에서 `installApp`/`uninstallApp` 호출 → 결과에 따라 `console.log`(성공 안내 문구, 설치면 "~/Applications에서 Finder로 열어 보세요. 저장소를 옮기면 이 명령을 다시 실행해 주세요." 포함) 또는 `console.error`(실패 이유) → `process.exitCode = result.ok ? 0 : 1`.
- 도움말 문자열에 `ai-office install-app [--uninstall]          데스크톱 앱을 ~/Applications에 설치(또는 삭제)` 한 줄 추가.

## `package.json` 변경

- `scripts`에 `"install-app": "node bin/ai-office.mjs install-app"` 추가.

## 아이콘

`desktop/icon.cjs`의 `markPng`를 그대로 쓴다(바이너리 자산을 저장소에 더하지 않는다는 지금 방식을 유지한다). 개인용 `AI Office.app`에 있는 기존 `icon.icns`는 쓰지 않는다. 저장소에 없는 파일이고, 재현할 수 있는 코드가 아니면 커밋에 넣을 수 없기 때문이다.

## README

"Ways to run" 절 아래에 "데스크톱 앱을 설치형으로 쓰기" 소절을 추가한다: Node 설치 → `git clone` → `npm ci` → `npm run install-app` → 첫 실행에서 서버 선택 화면 → (선택) 에이전트 훅 연결(`ai-office setup claude --write` 등, 기존 "Connect your tools" 절로 연결). 지우는 법(`node bin/ai-office.mjs install-app --uninstall`)도 한 줄 적는다. 다른 경로로 받은 사본에서 Gatekeeper 경고가 뜨면 `xattr -cr` 한 줄로 풀 수 있다는 안내도 넣는다.

## 바꾸지 않는 것(요구사항과 같음, 재확인)

- `desktop/main.cjs`, `desktop/target.cjs`, `desktop/choose.html`, PR #11의 Server 메뉴: 그대로 둔다.
- 개인용 `AI Office.app`(저장소 루트, 추적 제외): 지우거나 덮어쓰지 않는다. 새 설치 명령과 이름이 같아 보이지만 설치 위치(`~/Applications`)가 다르므로 서로 부딪히지 않는다.

## 설계 검토 반영(1회차, 독립 검토 에이전트 결과를 수정으로 반영)

이 절은 위 내용보다 우선한다.

1. **Electron Helper 앱(`Contents/Frameworks/Electron Helper*.app`)은 리네임하지 않는다.** Dock·Cmd+Tab·첫 메뉴 이름(요구사항의 핵심 목표)에는 영향이 없고, 각 Helper까지 통째로 리브랜딩하려면 번들마다 실행 파일을 다시 서명해야 해서 작업량이 크게 늘어난다. 활동 모니터·시스템 로그에는 "Electron Helper" 이름이 계속 보인다는 것을 알려진 제약으로 README와 설치 완료 메시지에 적는다.
2. **단일 인스턴스 잠금 공유는 고치지 않고, 알려진 동작으로 받아들인다.** `desktop/main.cjs`의 `app.setName('AI Office')`와 `requestSingleInstanceLock()`은 설치본과 소스 실행이 같은 이름을 쓰는 한 항상 같은 잠금을 공유한다(둘 중 하나만 창을 띄우고, 나중 것은 그 창을 앞으로 가져오기만 한다). 이것은 일반 사용자에게는 오히려 바라는 동작이다(같은 컴퓨터에서 사무실 창이 두 개 뜨는 것을 막아 준다). 다만 개발 중에는 "설치한 앱이 떠 있으면 소스를 고쳐 다시 실행해도 옛 창만 앞으로 올 뿐 새 코드가 반영되지 않는다"는 혼란을 줄 수 있으므로, README의 "데스크톱 앱을 설치형으로 쓰기" 절에 "코드를 고치며 테스트할 때는 먼저 설치한 앱을 Quit 하세요"라는 한 줄을 넣는다. 별도의 `userData`/잠금 키 분리는 두 인스턴스가 동시에 로컬 서버를 띄우는 등 더 큰 문제를 새로 만들 수 있어 하지 않는다.
3. **`codesign`은 `--deep` 없이 먼저 시도하고, 검증에 실패할 때만 `--deep`으로 다시 서명한다.** `--deep`은 Apple이 서명 용도로는 권장하지 않는 플래그다(하위 프레임워크를 한꺼번에, 개별 요구사항 없이 서명해 버린다). 여기서는 `Contents/Frameworks` 아래(Electron Framework, Helper 앱들)를 전혀 바꾸지 않고 원래의 유효한 서명을 그대로 두므로, 바뀐 부분(최상위 실행 파일, Info.plist, 새 `Resources/icon.icns`·`Resources/app/`)만 다시 서명하면 충분할 가능성이 높다. 순서: `codesign --force --sign - tmpApp` → `codesign --verify --deep --strict tmpApp`으로 전체 번들 검증 → 검증이 실패하면 그때 `codesign --force --deep --sign - tmpApp`으로 다시 서명한다(설계 10번 단계를 이 3단계로 바꾼다).
4. **`plistEdits`의 값에 큰따옴표(`"`)가 있으면 설치를 멈춘다.** PlistBuddy의 `-c` 파서는 큰따옴표로 값의 공백을 하나의 토큰으로 묶어 주지만, 값 자체에 `"`가 있으면 깨진다. 지금 넣는 값(앱 이름, bundle id, 저장소 `package.json`의 `version`)에는 해당하지 않지만, `plistEdits`를 실행하는 함수 맨 앞에서 `value.includes('"')`이면 `{ ok: false, error: '...' }`로 막아 조용히 깨지지 않게 한다.
5. **iCloud Desktop 동기화 위험을 구체적으로 적는다.** 이 컴퓨터의 저장소 경로(`~/Desktop/PDS/dev/ai-office`)는 `~/Desktop` 바로 아래에 있다. "데스크탑 및 문서 폴더" iCloud 동기화가 켜져 있으면, 저장소를 옮기거나 지우지 않아도 iCloud의 용량 최적화가 파일을 클라우드 전용(오프로드) 상태로 바꿀 수 있고, 그러면 `Resources/app/index.js`의 `require`가 실패해 앱이 안 켜질 수 있다. 설치 완료 메시지와 README에 "저장소가 iCloud Desktop 동기화 대상 폴더에 있으면 설치 전에 동기화를 끄거나 저장소를 다른 폴더로 옮기는 편이 안전하다"는 안내를 넣는다. `~/Applications`는 iCloud 동기화 대상이 아니므로 설치 위치 자체는 안전하다.
6. **`installApp`/`uninstallApp`의 단계 순서와 에러 경로도 자동 테스트로 덮는다.** 순수 함수 5개만으로는 "실패하면 중간 산출물을 지운다", "우리 앱이 아니면 덮어쓰지 않는다", `EXDEV` 폴백 같은, 운영 위험에서 가장 걱정한 부분을 테스트하지 못한다는 지적을 받아들인다. `installApp`/`uninstallApp`이 외부 명령 실행을 직접 `child_process.spawnSync`로 부르는 대신, `{ run = spawnSync, fs: fsModule = fs } = {}` 형태로 주입받게 하고, 테스트에서는 가짜 `run`(항상 성공/특정 단계에서만 실패)과 임시 폴더를 넣어 "N번째 단계에서 실패하면 임시 폴더가 지워지고 기존 `destApp`은 그대로인가", "식별자가 다르면 덮어쓰지 않는가" 같은 흐름을 검사한다. 이 테스트도 macOS 전용 도구를 실제로 부르지 않으므로 기존 CI의 Node 20/22/24 매트릭스에서 그대로 통과한다.
7. **`Resources/app` 로딩이 실패하면(기본 "Get Started" 화면이 뜨면) 알아챌 수 있게, 설치 자체에 자가 점검을 넣지는 않는다.** 이 저장소의 지금 electron 버전(44.7.0)에서 수동 검증(04-검증.md)으로 확인하는 것으로 충분하다고 보고 범위를 키우지 않는다. 대신 전제가 되는 electron 버전이 달라져 이 방식이 깨지면, 요구사항의 원칙대로(`resolveTemplateApp`이 이미 구조 검증을 한다) 설치가 알아들을 수 있는 오류로 멈추게 돼 있으므로 추가 조치는 열어 두되 이번 범위에는 넣지 않는다.
