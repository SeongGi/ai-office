작업 공간: `/Users/seonggi/Desktop/PDS/dev/ai-office-wt/desktop-installer` (브랜치 `feat/desktop-installer`, 기준 `origin/main` 039ae9a).

성기님 요청 원문(2026-11-09): "새롭게 설치형으로 만들어줘. 이 부분도 정리해서 깃헙에 올리구."

## 목표

- 다른 Mac에서 이 저장소를 받은 뒤 명령 한 번으로 `~/Applications/AI Office.app`을 만들게 한다. 지금 저장소 맨 위에 있는 개인용 실행 스크립트(node 경로를 하드코딩한 zsh 스크립트, `.git/info/exclude`로 추적에서 뺀 파일)를 대체한다.
- 설치한 앱은 Dock, Cmd+Tab 전환창, 맨 위 메뉴 막대 첫 항목에서 모두 "AI Office"로 보이게 한다. 지금 소스 설치(`node bin/ai-office.mjs app`)로 띄운 창은 Electron 실행 파일을 그대로 쓰므로 첫 메뉴 제목이 "Electron"으로 남는다(PR #11은 이 문제를 Server 메뉴를 따로 둬서 피해 갔을 뿐 고치지는 않았다).
- 다른 PC에 처음 설치하는 순서를 README에 정리한다.

## 범위 확정(성기님 확인, 2026-11-09)

- 앱 이름을 Dock·Cmd+Tab·첫 메뉴에서 "AI Office"로 보이게 하는 작업(Electron.app 복사 + Info.plist 변경 + 재서명)을 이번 작업에 포함한다.
- 설치 위치는 `~/Applications`로 한다.

## 현재 동작(확인한 사실)

- `bin/ai-office.mjs`의 `openApp()`은 `require('electron')`으로 `node_modules/electron`의 Electron 실행 파일 경로(문자열)를 얻어 `desktop/main.cjs`를 그 Electron으로 띄운다. Electron이 없으면 Chromium app-window로, 그것도 없으면 그냥 브라우저로 돌아간다(이 세 단계 fallback은 그대로 둔다).
- `electron`은 `package.json`의 `optionalDependencies`에 있다. 플랫폼이 맞으면 `npm ci`가 설치하고, 이미 `node_modules/electron/dist/Electron.app`로 내려받아져 있다(이 기기에서 확인: 버전 44.7.0, arm64, ad-hoc 서명 상태).
- `node_modules/electron/dist/Electron.app/Contents/Info.plist`는 `CFBundleName=Electron`, `CFBundleExecutable=Electron`, `CFBundleIdentifier=com.github.Electron`, `CFBundleIconFile=electron.icns`다. Electron은 이미 "adhoc,linker-signed" 상태이고, Apple Silicon은 서명 없는 실행 파일을 아예 거부하므로 번들을 고치면(실행 파일 이름, Info.plist, 아이콘을 바꾸면) 반드시 다시 서명해야 한다.
- Electron이 코드 없이 열리면 기본 "Get Started" 화면이 뜬다. `Contents/Resources/app/`(또는 `app.asar`) 폴더에 `package.json`+진입 스크립트를 두면 Electron이 그것을 기본 화면 대신 연다. 지금 `desktop/main.cjs`는 상대 경로(`./icon.cjs`, `../shared/env.cjs`, `../server/index.mjs`)로만 자기 파일들을 찾으므로, `Resources/app/index.js`가 저장소 경로의 `desktop/main.cjs`를 `require`하기만 하면(코드 복사 없이) 그 상대 경로들이 전부 저장소 안에서 그대로 맞는다. `require('electron')`은 메인 프로세스 안에서 돌 때는 Electron이 내장 모듈로 주므로 `node_modules`가 따로 없어도 된다.
- `desktop/icon.cjs`의 `markPng(size, opts)`가 이미 PNG를 코드로 그린다(바이너리 자산 없이). 개인용 `AI Office.app`에는 이미 만들어 둔 `icon.icns`가 있다(참고용으로 보되, 설치 스크립트는 새로 만든다. 재현할 수 있어야 커밋에 들어갈 수 있기 때문이다).
- 개인용 `AI Office.app`의 `Info.plist`는 `LSUIElement=true`(Dock에 아이콘이 없고 메뉴 막대 아이콘만 보임)로 돼 있다. 이는 그 스크립트가 `bin/ai-office.mjs app`을 실행해 **진짜** Electron 앱을 새로 띄우는 겉핥기 런처였기 때문이다(진짜 창은 그 안에서 뜬 두 번째 프로세스가 가진 Dock 아이콘을 쓴다). 이번에 만드는 앱은 겉핥기가 아니라 Electron.app 자체이므로 `LSUIElement`를 넣지 않는다(Dock 아이콘이 정상적으로 보여야 한다).

## 하지 않을 것

- Windows·Linux용 네이티브 설치 앱은 다루지 않는다. 그 플랫폼은 지금처럼 Chromium app-window 또는 브라우저로 돌아간다.
- Apple 개발자 계정으로 한 공증(notarization)은 하지 않는다. ad-hoc 서명(`codesign --sign -`)만 한다. 이 컴퓨터에서 직접 만든 앱이라 인터넷에서 받았을 때 붙는 격리 속성(`com.apple.quarantine`)이 없고, 그래서 보통은 서명 경고 없이 바로 켜진다.
- 저장소 코드를 앱 번들 안에 복사하지 않는다. `Resources/app/index.js`는 설치 시점의 저장소 경로를 가리키기만 한다. 저장소를 지우거나 옮기면 앱이 깨지는 것은 알려진 제약으로 문서화하고, 다시 설치(또는 경로를 다시 구워 넣는 명령)로 고치게 한다.
- PR #11에서 만든 "Server" 메뉴와 상태 막대 아이콘의 "Change server…"는 그대로 둔다. 소스 설치(이번 설치 명령을 쓰지 않은 실행)에서는 여전히 필요하다.
- `npm publish`로 배포하는 패키지 자체의 구조는 바꾸지 않는다(이 저장소를 clone해 쓰는 사용자를 대상으로 한다).

## 성공 기준

1. 새로 clone한 저장소에서 `npm ci` 다음 `npm run install-app`(또는 같은 일을 하는 `node bin/ai-office.mjs install-app`) 한 번으로 `~/Applications/AI Office.app`이 생긴다.
2. 만든 앱을 Finder나 Launchpad에서 더블클릭하면 켜지고, Dock 아이콘 우클릭 메뉴, Cmd+Tab 전환창, 맨 위 메뉴 막대 첫 항목이 모두 "AI Office"로 보인다(지금의 "Electron"이 아니다).
3. 저장된 서버 선택이 없는 첫 실행이면 지금과 똑같이 `choose.html` 화면이 뜨고, 고른 뒤에는 그 서버로 붙는다. `ai-office app --url ...`로 저장한 선택도 그대로 따른다.
4. 같은 설치 명령을 다시 실행하면(이미 앱이 있어도) 에러 없이 새로 고쳐 만든다(덮어쓰기).
5. 지우는 명령(`node bin/ai-office.mjs install-app --uninstall`)으로 설치한 앱만 안전하게 지운다. 그 위치에 우리가 만들지 않은 다른 앱이 있으면 지우지 않고 오류 메시지를 낸다.
6. macOS가 아닌 플랫폼에서 설치 명령을 실행하면 뜻을 알 수 있는 오류 메시지를 내고 조용히 끝낸다(앱 설치는 시도하지 않는다).
7. 기존 동작은 전혀 바뀌지 않는다: `ai-office`, `npm start`, 훅 자동 실행, 소스 설치로 띄운 창의 Server 메뉴.
8. README에 다른 PC에 처음 설치하는 순서(Node 설치 → clone → `npm ci` → 앱 설치 → 서버 연결 → 훅 설치)를 한 절로 정리한다.
9. `npm test` 전체가 그대로 통과하고, 새로 만든 로직(Info.plist 값 계산, 경로 계산, identifier 확인 등 Electron 없이도 테스트할 수 있는 부분)에는 새 테스트가 있다. 실제 `.app` 번들을 만들고 서명하는 부분은 이 컴퓨터에서 수동으로 확인한다(CI에는 Electron 실행 파일이 없을 수 있고, 서명·앱 설치는 테스트 스위트의 책임이 아니다).

## 운영 위험

- Apple Silicon은 서명되지 않은 실행 파일을 아예 거부한다. 번들을 고친 뒤 재서명을 빠뜨리면 더블클릭했을 때 바로 꺼지거나 "손상되었습니다" 오류가 나므로, 재서명 단계는 설치 과정에서 건너뛸 수 없게 만든다.
- 이미 `~/Applications/AI Office.app` 위치에 사용자가 다른 용도로 만든 앱이 있으면 설치·삭제가 그 앱을 건드릴 수 있다. `CFBundleIdentifier`로 우리가 만든 앱인지 확인해 방지한다.
- `node_modules/electron`의 내부 구조(실행 파일 이름, Info.plist 키, 아이콘 파일 이름)는 npm `electron` 패키지 버전이 바뀌면 같이 바뀔 수 있다. 지금 설치된 44.7.0 기준으로 만들고, 구조가 달라지면 설치 명령이 알아들을 수 있는 오류를 내게 한다(조용히 깨진 앱을 만들지 않는다).
- 저장소 폴더를 옮기거나 지우면 앱이 깨진다. README와 설치 완료 메시지에 "저장소를 옮기면 설치를 다시 하라"고 적어 둔다.
- `ditto`로 복사한 뒤 바로 서명하지 않은 상태의 중간 산출물이 디스크에 남을 수 있다. 그래서 설치 명령은 임시 위치에서 작업하고 마지막에만 `~/Applications`로 옮기는 방식으로, 중간에 실패해도 기존 앱이 반쯤 고쳐진 채 남지 않게 한다.

## 열린 질문(설계 단계에서 정한다)

- `CFBundleIdentifier` 값을 무엇으로 할지(예: `kr.seonggi.ai-office` 대신 저장소 이름을 딴 일반적인 값).
- 아이콘을 `desktop/icon.cjs`의 `markPng`로 새로 그릴지, 개인용 `AI Office.app`에 이미 있는 `icon.icns`를 그대로 쓸지 정한다. 후자는 저장소에 없는 파일이라 커밋에 넣을 아이콘 생성 코드가 새로 필요하다.
- 설치 명령 이름(`install-app`/`install-desktop-app` 등)과 지우기 플래그 형태(`--uninstall` 플래그 대 별도 하위 명령).
