# 02 설계

## A. 훅이 세션 제목을 이름으로 보낸다

- `adapters/transcript.mjs`
  - `parseTranscriptTitle(tail)`: 끝에서부터 줄을 읽어 마지막 `customTitle`(문자열, 비어 있지 않음)을 찾고, 없으면 마지막 `aiTitle`을 찾는다. JSON으로 읽지 못하는 줄은 건너뛴다. 없으면 `undefined`.
  - `readTranscriptTitle(path, size)`: 파일 끝 64KB를 읽어 위 함수에 넘긴다. 실패하면 `undefined`.
  - `shortTitle(title)`: 공백을 한 칸으로 줄이고 14자가 넘으면 13자 + `…`. seed의 기존 규칙과 같다.
- `adapters/claude.mjs`
  - 이름 우선순위: `AGENT_FLOOR_NAME` 환경 변수 > `opts.name` > 세션 제목(`input.transcript_path`가 문자열일 때 `shortTitle(readTranscriptTitle(...))`) > 기본(`Claude` 또는 `Codex`).
  - 제목은 메인 세션 이벤트(`base`)에만 쓴다. 서브에이전트(`actor`가 sub인 경우)에는 이름이 들어가지 않는다(지금과 같다).
  - Stop에서 이미 읽는 꼬리 읽기와 합칠 수 있으면 한 번만 읽는다(선택).
- `adapters/seed.mjs`: 자체 `titleOf` 대신 `readTranscriptTitle` + `shortTitle`을 써서 `customTitle`도 따른다.
- 서버의 기존 규칙(기본 이름 `Claude`, `Codex`는 구체적인 이름을 덮지 않는다)은 그대로 둔다.

## B. 관리자가 이름을 직접 고친다

### 프로토콜 (`shared/protocol.js`, `shared/protocol.d.ts`)

- 이벤트 종류에 `rename`을 더한다. `{type:'rename', agent, name}`. `name`은 40자에서 자른다(기존 clip).
- `applyEvent`: `rename`은 그 직원이 이미 있을 때만 `agent.name = ev.name`(기본 이름 규칙을 거치지 않고 그대로 넣는다). 직원이 없으면 아무것도 만들지 않는다. 기록(history)에 남기지 않고, 상태와 `lastSeen`도 바꾸지 않는다. 그래서 `ensureAgent`보다 앞에서 처리하고 돌아간다.
- `docs/protocol.md`에 한 줄 적는다.

### 서버 (`server/index.mjs`)

- 메모리 맵 두 개
  - `customNames`: 직원 id -> 관리자가 고친 이름. 파일로 남긴다.
  - `hookNames`: 직원 id -> 훅이 마지막으로 보낸 구체적인 이름(기본 이름 제외). 고친 이름을 지울 때 되돌릴 값.
- 저장 파일: `AGENT_FLOOR_NAMES` 환경 변수, 없으면 감사 기록과 같은 폴더의 `names.json`. 시작할 때 읽고(없거나 깨졌으면 빈 맵), 바뀔 때마다 임시 파일에 쓴 뒤 이름을 바꿔 덮는다. 쓰기 실패는 요청을 막지 않는다. 최대 500개, 넘으면 오래된 것부터 지운다(삽입 순서).
- `ingest`: 정규화한 이벤트가 이름을 가지고 있고 기본 이름이 아니면 `hookNames`에 적는다. 그 직원에 `customNames`가 있으면 이벤트의 `name`을 고친 이름으로 바꾼 뒤 적용한다. `rename` 이벤트는 `/events`(외부)로 들어와도 받지 않는다(관리자 길로만 만든다). 기계용 포트도 같은 `ingest`를 쓰므로 함께 막힌다.
- `POST /rename {agent, name}`
  - `canControl`이 아니면 403, 감사 기록 `kind:'rename', result:'denied'`.
  - 직원이 없으면 404.
  - `name`을 trim. 40자 넘으면 400.
  - 비어 있으면 `customNames`에서 지우고, 되돌릴 이름은 `hookNames`의 값, 없으면 지금 이름을 그대로 둔다.
  - 아니면 `customNames`에 저장.
  - 내부에서 `rename` 이벤트를 만들어 적용하고 방송한다. 결과 `{ ok: true, name }`.
  - 감사 기록 `kind:'rename', result:'ok', text: 새 이름`.
- 기계용 포트에는 길을 더하지 않는다. oauth2-proxy의 로그인 생략 경로에도 더하지 않는다.

### 화면 (`src/ui/hud.ts`, `src/ui/labels.ts`, `src/core/connection.ts`, `src/styles.css`)

- `connection.ts`: `renameAgent(id, name)`가 `POST /rename`을 부르고 `{ok, name}` 또는 `{ok:false, reason}`를 돌려준다(`sendInstruction`과 같은 모양).
- 카드 머리의 이름(`h2`) 옆에 연필 아이콘 버튼. `controlAllowed()`이고 라이브 모드이고 메인 세션일 때만 보인다.
- 누르면 이름 글자가 있던 곳이 입력칸(최대 40자)과 저장, 취소 버튼으로 바뀐다. Enter는 저장, Esc는 취소. 빈 칸 저장은 "세션 제목으로 돌아가요" 안내와 함께 지우기다.
- 카드는 상태가 바뀔 때마다 다시 그려진다. 고치는 중이면 다시 그려도 입력칸, 쓰던 글, 커서 자리를 유지한다(지시 칸의 `drafts` 처리와 같은 방식). 다른 직원을 고르면 고치기 상태는 끝난다.
- 실패하면 입력칸 아래에 사유를 보여 준다.

## C. 함께 고치는 것

- "하는 일": `job`과 `a.activity`가 같으면 `now-text` 줄을 그리지 않는다.
- 퇴사 안내(`leaveNote`): 실제 동작에 맞춰 "세션도 닫아요. 일하는 중이면 화면에서만 내보내요."처럼 고친다. `/close`가 거절되면 화면에서만 내보내는 기존 흐름(`dismissAgent`)을 확인해서 문구를 맞춘다.

## 검토 1회차 반영 (이 절이 위 내용보다 앞선다)

1. `/rename`은 메인 세션만 받는다. `parent`가 있거나 `role !== 'Lead'`이면 400. `hookNames`도 `parent`가 없는 이벤트만 적는다.
2. 카드 `cardKey`에 `a.name`을 넣는다. 이름을 고치는 중에는 카드를 다시 그리지 않는다(입력칸 유지가 가장 단순하다). 다른 직원을 고르거나 저장, 취소하면 고치기 상태가 끝나고 다시 그린다.
3. 서버에 내부 전용 `applyAndBroadcast(ev)`(정규화, 적용, 방송)를 둔다. `ingest`는 `raw.type === 'rename'`이면 정규화 전에 거절한다(`normalizeEvent`는 클라이언트도 쓰므로 거기서 막지 않는다). 거절 테스트는 메인 포트와 기계용 포트 둘 다 둔다. 로그인한 비관리자가 `/events`로 아무 이벤트나 보낼 수 있는 것은 기존 문제로 이번 범위 밖이다.
4. 고친 이름을 지우면 `hookNames` 값으로, 없으면 `Claude`로 되돌린다(서버 재시작 직후 포함).
5. `names.json`은 seed보다 먼저 읽는다. 저장은 하나씩 순서대로 쓴다(앞 쓰기가 끝난 뒤 다음 쓰기). 같은 id를 다시 저장하면 지웠다가 다시 넣어 순서를 갱신한다. `hookNames`도 500개 상한을 둔다.
6. 훅은 제목을 `SessionStart`, `UserPromptSubmit`, `Stop`에서만 읽는다. 다른 훅은 이름을 `Claude`로 보내고 서버의 기본 이름 규칙이 기존 제목을 지킨다. 알려진 한계: `/rename` 기록 줄이 끝 64KB 밖으로 밀리면 `aiTitle`이 쓰인다. 이 경우 화면에서 직접 고치면 된다.
7. 감사 기록: 거절(denied)에도 시도한 이름을 `text`로 남기고, 404와 400도 `result`에 적는다. `name`이 문자열이 아니면 400, 40자 판정은 trim 뒤 길이로 한다.
8. `/rename`은 `status === 'offline'`이면 거절한다. 같은 id가 다시 join하면 고친 이름이 적용되고, `reset` 뒤에도 `customNames`는 남는다.
