# 실제 오피스 고양이 대화 — 요구사항

## 배경

데모에서는 고양이들이 몇 초마다 서로 말을 건다. 대사는 `shared/demo-script.js`의 `CHAT`에서 무작위로 고른 문장이다. 실제 오피스에서는 Claude 훅이 `message`를 서브에이전트 시작(실제 작업 설명)과 종료(고정 문구 `보고서 준비됐어요`) 때만 보내므로, 대화가 거의 보이지 않는다. 쉬는 방 말풍선은 `ㅋㅋ`, `!`, `z` 같은 감탄사뿐이다.

## 목표

실제 오피스에서도 고양이들이 서로 대화한다. 대사는 각 고양이의 실제 작업 정보로 조립한다.

- 같은 팀(같은 방) 고양이끼리는 책상에서 대화한다. 종이비행기와 말풍선이 함께 나온다.
- 쉬는 방(주방, 게임룸, 라운지)에 함께 있는 고양이끼리는 팀과 상관없이 대화한다. 바로 옆이므로 종이비행기 없이 말풍선만 띄운다.
- 대화 한 번은 말 거는 쪽 한 줄과 받는 쪽 한 줄, 모두 두 줄이다.
- 대사에는 그 고양이의 지금 하는 일(`activity`), 맡은 작업(`task`), 마지막 답(`lastReply`), 상태(`status`)를 쓴다.

## 하지 않을 것

- LLM이나 외부 API를 부르지 않는다. 대사는 브라우저 안에서 문장 틀로 만든다.
- 서버로 아무것도 보내지 않는다. 지어낸 대화를 서버 상태나 직원 기록(`history`)에 남기지 않는다.
- 3D 화면은 이번 범위에서 뺀다(기본 화면은 2D다).
- 훅과 어댑터(서브에이전트 보고 문구 등)는 바꾸지 않는다.
- 데모 대본의 기존 대화는 바꾸지 않는다.

## 성공 기준

1. 같은 팀에 고양이가 둘 이상 책상에 있으면, 몇십 초 안에 실제 작업 내용이 들어간 두 줄 대화가 보인다.
2. 쉬는 방에 고양이 둘 이상이 있으면, 그 방에서 실제 작업 내용이 들어간 두 줄 대화가 보인다.
3. 혼자 있는 고양이는 대화하지 않는다. 퇴근(`offline`)하거나 떠나는 고양이는 대화에 끼지 않는다.
4. 대사 한 줄은 짧다(본문 40자 안팎으로 자른다). 줄바꿈과 마크다운 기호는 지운다.
5. 한 화면에 동시에 진행되는 지어낸 대화는 많지 않다. 같은 고양이가 연달아 말하지 않는다.
6. 실제 `message`(서브에이전트 지시와 보고)가 최근에 오간 팀에서는 지어낸 책상 대화를 쉰다. 데모처럼 이미 대화가 많은 곳에서는 저절로 줄어든다.
7. 움직임 줄이기 설정에서도 말풍선은 보이고, 종이비행기 대신 기존의 물결 표시를 쓴다.
8. 대사 조립은 순수 함수이며 `node --test`로 검사한다. 기존 테스트 59개는 계속 통과한다.

## 운영 위험

- **정보 노출:** 대사는 같은 화면의 직원 카드에 이미 보이는 정보만 쓴다. 실제 오피스는 로그인한 사람만 본다. 외부 데모는 가짜 데이터만 있다.
- **소음:** 대화가 너무 잦으면 화면이 산만해진다. 간격과 동시 진행 수에 상한을 둔다.
- **화면마다 다름:** 대화는 보는 사람의 브라우저에서 만들어지므로, 두 사람이 보는 대화가 서로 다르다. 기록이 아니라 분위기 연출이므로 받아들인다.
- **성능:** 프레임마다 무거운 계산을 하지 않는다. 대화 후보 고르기는 1초에 한 번 정도로 충분하다.

## 열린 질문

- 대화 간격 수치(기본값)는 구현 후 화면을 보며 조정한다. 설계에서 초깃값을 정한다.
