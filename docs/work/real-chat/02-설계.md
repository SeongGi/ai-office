# 실제 오피스 고양이 대화 — 설계

요구사항은 `01-요구사항.md`에 있다. 이 설계는 두 부분으로 나뉜다. 대사를 만드는 순수 모듈(`shared/chatter.js`)과, 2D 화면에서 대화할 짝과 시각을 고르는 드라이버(`src/world2d/chatter2d.ts`)다.

## 1. 대사 모듈 `shared/chatter.js` (순수 함수, 브라우저와 Node 공용)

`shared/places.js`와 같은 방식으로 JS 파일과 `.d.ts`를 함께 둔다. 난수는 인자로 받는 함수(`rnd: () => number`)만 쓴다. 그래서 테스트에서 결과를 고정할 수 있다.

### 1.1 `cleanLine(text, max = 40)`

- 입력이 문자열이 아니거나 비면 `''`을 돌려준다.
- 코드 블록 표시(```)와 인라인 코드 백틱을 지운다. `**굵게**`, `*기울임*`, `__굵게__`처럼 짝을 이룬 강조 표시만 지우고, 낱자 `_`와 `*`는 남긴다(`user_id`가 망가지지 않게). 줄 머리의 제목 표시(`# `), 인용 표시(`> `), 목록 머리(`- `, `1. `)를 지운다. 줄 가운데의 `#`(예: `PR #12`)은 남긴다.
- 줄바꿈과 연속 공백을 공백 하나로 합친다.
- 첫 문장만 남긴다. 문장 끝은 `. `, `! `, `? ` 또는 원문의 줄 끝으로 본다. 첫 문장이 6자보다 짧으면 둘째 문장까지 남긴다.
- 그래도 `max`자를 넘으면 `max - 1`자에서 자르고 `…`을 붙인다. 글자 수는 코드 포인트 기준이다(`[...s]`).

### 1.2 `topicOf(agent)`

고양이 한 마리가 지금 이야기할 거리를 고른다. 결과는 `{ kind, text }`다. 위에서부터 처음 맞는 것을 쓴다.

| 조건 | kind | text |
| --- | --- | --- |
| `status === 'error'` | `error` | `activity` |
| `status === 'waiting'` | `waiting` | `activity` |
| `status`가 `working` 또는 `thinking`이고 `activity`가 있음 | `busy` | `activity` |
| `status`가 `idle` 또는 `done`이고 `lastReply`가 있음 | `done` | `lastReply` |
| `task`가 있음 | `task` | `task` |
| 그 밖 | `none` | `''` |

`text`는 모두 `cleanLine`을 거친다. 정리 결과가 빈 문자열이면 다음 조건으로 넘어간다. `task`는 `Agent` 타입에 없지만 팀의 `task`가 있으므로, 함수는 `topicOf(agent, teamTask)`처럼 팀 작업을 둘째 인자로 받는다.

### 1.3 `makeChat(a, b, opts)`

- 인자: 말 거는 고양이 `a`, 받는 고양이 `b`(둘 다 `Agent`), `opts = { rnd, teamTaskA, teamTaskB, where }`. `where`는 `'desk'` 또는 `'break'`다.
- 둘 다 `none`이면 `null`을 돌려준다(할 말이 없다).
- `a`가 `none`이고 `b`에 이야깃거리가 있으면 `a`가 묻는 문장(예: `{b}, 요즘 뭐 해요?`)으로 시작한다.
- 돌려주는 값은 두 줄이다: `[{ from: a.id, to: b.id, text }, { from: b.id, to: a.id, text }]`.
- 문장 틀은 kind마다 3개 이상 두고 `rnd`로 고른다. 말투는 데모 대본과 같은 해요체다. 틀 안의 `{to}`는 상대 이름, `{x}`는 정리된 이야깃거리다.
- 쉬는 방(`where === 'break'`)에서는 여는 말 앞에 방 분위기 말을 가끔(절반 확률) 붙인다(예: `커피 마시면서 하는 얘긴데,`). 이 때문에 한 줄이 50자를 넘지 않도록, 머리말을 붙일 때 `{x}`를 30자로 줄인다.

문장 틀 예시(구현에서 다듬어도 된다):

- 여는 말: busy `{to}, 저 지금 {x}`, done `방금 끝냈어요. {x}`, error `막혔어요… {x}`, waiting `저 답 기다리는 중이에요. {x}`, task `요즘 '{x}' 하고 있어요`
- 받는 말: busy `저는 {x}`, done `저도 방금 하나 끝냈어요. {x}`, error `저도 막혔어요. {x}`, waiting `저는 승인 기다리는 중이에요`, task `저는 '{x}' 맡았어요`, none `오 좋네요!`, `수고 많아요`

## 2. 드라이버 `src/world2d/chatter2d.ts`

### 2.1 인터페이스

```ts
export interface ChatLine { from: string; to: string; text: string; plane: boolean }
export class Chatter2D {
  /** 1초에 한 번 후보를 보고, 시각이 된 줄을 emit으로 내보낸다. t는 World2D의 elapsed(초). */
  update(t: number, state: WorldState, agents: Map<string, Agent2D>, emit: (line: ChatLine) => void): void;
  /** 실제 message가 오가면 부른다. 보낸 팀과 받는 팀의 책상 대화를 잠시 쉬고, 두 고양이를 방금 말한 것으로 친다. */
  noteRealMessage(fromId: string, toId: string, teams: string[], t: number): void;
  /** 떠난 고양이를 잊는다. 진행 중인 대화에 끼어 있으면 그 대화를 버린다. */
  forget(id: string): void;
  clear(): void;
}
```

### 2.2 짝 고르기 (1초에 한 번)

- **책상 짝:** 같은 팀이고, 둘 다 `place`가 `'desk'`이거나 둘 다 `'meeting'`이고, `mode`가 `'seated'` 또는 `'standing'`이다(도착한 고양이만). 회의(`state.meeting`)가 열려 있으면 `'meeting'` 짝은 고르지 않는다. 전체 회의 때 여러 팀이 섞이기 때문이다.
- **쉬는 방 짝:** `place`가 같은 쉬는 방(`'kitchen'`, `'games'`, `'lounge'`)이고, `mode`가 `'seated'` 또는 `'standing'`이다. 팀은 따지지 않는다.
- 공통 제외: `status`가 `offline`, `leaving` 플래그, `farewell` 중인 고양이, 지금 다른 대화에 끼어 있는 고양이, 최근 40초 안에 말한 고양이.
- 무리(팀 또는 쉬는 방)마다 다음 대화 시각을 둔다. 책상 무리는 30~50초, 쉬는 방 무리는 18~30초 뒤로 정한다(난수). 무리가 처음 보이면 4~10초 뒤로 정한다.
- 책상 무리는 그 팀에 실제 `message`가 오간 뒤 30초 동안 쉰다.
- 동시에 진행되는 지어낸 대화는 화면 전체에서 2개까지다.
- 시각이 된 무리에서 말 거는 고양이와 받는 고양이를 난수로 고르고, `makeChat`을 부른다. `null`이면 그 무리의 다음 시각만 미룬다.

### 2.3 대화 진행

- 첫 줄은 바로 내보내고, 둘째 줄은 2.8초 뒤에 내보낸다.
- 둘째 줄을 내보내기 전에 다시 확인한다. 두 고양이가 아직 `agents`에 있고, `leaving`과 `farewell`이 아니며, `status`가 `offline`이 아니고, `place`가 처음과 같아야 한다. `mode`는 보지 않는다. 쉬는 방 고양이는 방 안에서 잠깐 걷기도 하기 때문이다(`activities.ts`의 짧은 나들이). 조건이 깨지면 대화를 버린다.
- `plane`은 책상 짝일 때 `true`, 쉬는 방일 때 `false`다.

### 2.4 난수

`Math.random`을 기본으로 쓰되, 생성자에서 `rnd`를 받을 수 있게 해서 시험할 때 고정한다.

## 3. `World2D` 연결

- 필드 `private chatter = new Chatter2D()`.
- 프레임 갱신(`this.life.update`를 부르는 근처)에서 `this.state`가 있을 때 `this.chatter.update(this.elapsed, this.state, this.agents, (l) => this.showLine(l))`. 움직임 줄이기 설정에서도 부른다.
- `showLine(l)`: 두 고양이가 모두 있을 때만 `from.say(2.4)`, `this.cb.onMessage(l.from, l.to, l.text)`. `l.plane`이면 `handleEffect`와 같은 방식으로 종이비행기(움직임 줄이기면 물결)를 더한다. 이 부분은 `handleEffect`의 해당 코드를 작은 메서드(`sendLetter(from, to)`)로 빼서 둘이 같이 쓴다.
- `handleEffect`에서 실제 `message`가 오면 `this.chatter.noteRealMessage(effect.from, effect.to, [from.team, to.team], this.elapsed)`. 다른 팀으로 간 메시지도 받는 팀의 책상 대화를 쉬게 한다. 두 고양이의 최근 말한 시각도 갱신되므로, 40초 제외 규칙이 실제 말풍선을 지켜 준다(HUD 말풍선은 고양이당 하나라 덮어쓰기 때문이다).
- `dropAgent`에서 `this.chatter.forget(id)`, `reset`에서 `this.chatter.clear()`.
- 서버에는 아무것도 보내지 않으며 `store`도 바꾸지 않는다. 그래서 직원 기록에 남지 않는다.

## 4. 시험

`test/chatter.test.mjs` (Node, 브라우저 없음):

1. `cleanLine`: 마크다운과 줄바꿈 제거, 첫 문장 고르기, 40자 자르기와 `…`, 한글 코드 포인트 기준 길이, 빈 값.
2. `topicOf`: 표의 우선순위 각각, 정리 후 빈 값이면 다음 조건으로 넘어가기.
3. `makeChat`: 둘 다 `none`이면 `null`, 두 줄의 from/to가 서로 반대, 대사에 실제 `activity`가 들어감, `a`가 `none`이면 묻는 말로 시작, 쉬는 방 머리말이 붙어도 한 줄이 50자 이하.
4. 고정 `rnd`로 같은 입력이면 같은 결과.
5. 쉬는 방 짝의 흔한 경우: 둘 다 `idle`이고 `lastReply`만 있다. 이때도 대화가 만들어진다.

기존 테스트는 이 서버기기 셸에 `AGENT_FLOOR_URL`, `AGENT_FLOOR_TOKEN`, `AGENT_FLOOR_DEVICE`가 들어 있어 5개가 실패한다. 그래서 `env -u AGENT_FLOOR_URL -u AGENT_FLOOR_TOKEN -u AGENT_FLOOR_DEVICE npm test`로 돌린다.

드라이버는 DOM이 필요 없도록 `Agent2D`에서 쓰는 필드(`id`, `team`, `place`, `mode`, `leaving`, `farewell`)만 읽는다. 그래서 가짜 객체로 Node에서도 시험할 수 있지만, TS 파일이므로 이번에는 화면 확인(데모 모드와 실제 서버 화면)으로 검증한다.

## 5. 바꾸지 않는 것

훅, 어댑터, 서버, `shared/protocol.js`, 데모 대본, 3D 화면.

## 6. 설계 검토 반영 (1회차, 승인)

- 둘째 줄 확인에서 `mode`를 빼고, 처음 고를 때만 도착한 고양이(`seated`, `standing`)를 요구한다.
- 다른 팀으로 간 실제 메시지도 받는 팀을 쉬게 하고, 실제 메시지를 주고받은 두 고양이를 방금 말한 것으로 친다.
- `cleanLine`이 `user_id`, `PR #12` 같은 내용을 망가뜨리지 않게 고쳤다.
- 회의가 열려 있으면 회의실 짝은 고르지 않는다.
- 받아들인 점: 쉬는 방 고양이는 `idle`이므로 이야깃거리가 `lastReply`와 팀 작업뿐이며, 둘 다 없으면 조용하다. 쉬는 방의 캔버스 감탄사와 HUD 말풍선이 잠깐 겹칠 수 있다. 동시 진행 상한(2개)은 실효가 작지만 비용이 없어 남긴다.
